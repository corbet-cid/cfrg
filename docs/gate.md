# gate

`cfrg gate` is the one place that writes to GitHub: it pushes the newest state of a repository from a local source (the git copy), under budgets, so a burst of
work on the primary forge can never become a burst of pushes on GitHub.

```sh
cfrg gate --config gate.json status
cfrg gate --config gate.json enqueue org/repo ...
cfrg gate --config gate.json create org/repo --private --description "..."   # dry run
cfrg gate --config gate.json flush              # dry run: prints what it would push
cfrg gate --config gate.json flush --create     # dry run: also prints a missing destination it would create and fill
CFRG_GITHUB_TOKEN=... cfrg gate --config gate.json flush --execute
CFRG_GITHUB_TOKEN=... cfrg gate --config gate.json flush --create --execute
cfrg gate --config gate.json dispatch org/repo ccid-remote.yml main --input job=macos --input sha=<40 hex>   # dry run
CFRG_GITHUB_TOKEN=... cfrg gate --config gate.json dispatch org/repo ccid-remote.yml main --input k=v --execute
```

| Rule | Behaviour |
|---|---|
| Queue | holds repository names, never commits; queueing twice keeps the first time; a flush pushes the newest state of every branch and tag once (N commits, one atomic push) and skips a repository that is in sync: nothing to create, fast-forward or prune (a default branch that exists only on GitHub does not count) |
| Budgets | defaults: 20 pushes per hour and 120 per day overall, 8 per hour per organisation, 10 minutes between pushes to one repository, 3 new repositories per day per organisation and 6 overall, 30 Actions runs per day. Any of them may be overridden under `budgets` |
| Lanes | a repository with `lane: "build"` (its GitHub Actions must build current code) goes first, may use the reserved slice (`build_reserve_per_hour` 6, `build_reserve_per_day` 30) that the bulk lane cannot, and every push to it is counted as an Actions run |
| Ledger | `state_dir/ledger.jsonl`, append-only; a mutation is recorded before it is made, so a crash can only over-count |
| Pause | `paused_dir/<org>` exists = that organisation is refused (written by a flag probe, or by the gate itself on the first 403, 429, 402 or abuse answer; never removed by the gate) |
| Kill switch | `kill_switch` directory exists = nothing is written, for every organisation |
| Atomic push | the push is `git push --atomic --no-verify --porcelain` with one explicit `<object>:<ref>` refspec per planned change (so a branch the primary moves or recreates after the plan cannot slip in or be deleted by accident, and a refused ref is listed per ref on stdout): every ref or none. A ref the destination refuses can no longer leave the copy half updated (the 2026-11-13 ccvl push landed a tag and three branches while `main` failed, and started a release workflow with the tag). `--no-verify` keeps a `pre-push` hook of the source (`git lfs install` writes one that uploads payloads) from running |
| Diverged copy | before any push slot is spent, the plan compares the source with the destination (`ls-remote`, a read): a branch whose destination tip is not an ancestor of the source's (`git merge-base --is-ancestor` in the source; a tip the source lacks cannot be one) is `non-fast-forward`, a tag standing at another object is `moved-tag`. Either makes the repository *diverged* (the copy no longer matches the primary and a push without force cannot fix it): it is **held, reported and not pushed**, with no ledger entry, no retry and no budget burnt. `status` lists it under `diverged` (`hold`, `refs`, `refs_total`, `since`, `seen`) and the same object is in `state_dir/diverged.json`, which the nightwatch and the status page read. Reading the destination is free (the flush reads every queued destination anyway, so a held repository adds no read), so the hold stays queued and clears itself on the first flush that finds the cause gone (the copy reconciled by a person, or the primary changed); a record of a repository that left the configuration is dropped; a dry run reports a hold and records nothing. A hold stops every ref of the repository, because the push is atomic. A repository that must keep flowing branches while its tags differ sets `hold_tags` |
| Rejected push | a push the destination refuses after the plan passed (a protection rule, a hook, a race, a stale lease) is recognised by the per-ref `[rejected]` / `[remote rejected]` status lines on stdout, not by the exit status (a transport failure in the middle of a push exits 1 too and lists no ref: it is `push failed`, stays queued and is tried again by the next flush); a refusal is recorded as `push-rejected` with the fingerprint of the exact push (refs changed, source and destination objects). Nothing was pushed (atomic). The same fingerprint is not tried again, on no clock (the events are a new commit on the primary or a change on the destination); a different fingerprint is a new push and spends one slot |
| Pruning | a branch or tag that exists only on the copy is deleted in the same push (`:refs/heads/x` or `:refs/tags/x` refspecs under `--force-with-lease=<ref>:<object seen>`, so a ref that moved after the destination was read is not deleted; the copy matches the primary). Never pruned: `refs/heads/cforge/*` (the router's relay heads), `refs/pull/*` and every other namespace (the gate lists branches and tags only), the destination's default branch (GitHub refuses to delete it, which would fail the whole atomic push), and anything at all when the source has no branch. `max_prune` (default 10): a plan with more copy-only branches is held as `prune-limit` and nothing is deleted, because a source that lost branches by accident must never empty a destination; raise it in the configuration to let a larger clean-up through |
| LFS | payloads are **not** replicated to a copy; the push carries the pointer files (free plans limit LFS storage), so the gate never calls `git lfs`. The explicit per-repository exception is `"lfs": "payload"` under the repository: after a successful push `git lfs push --object-id` uploads the objects the source references. Absent = pointers only |
| Tag hold | `"hold_tags": true` in the configuration = branches only: no tag is pushed, and tags are left out when the source is compared with the destination (a tag that differs does not make a repository "out of sync"; `status` reports `hold_tags`). Tags already at the destination stay; setting it back to `false` pushes the tags that waited. Default `false`. Operator reason: a `v*` tag on GitHub can start a release workflow |
| Relay namespace | `refs/heads/cforge/*` on GitHub belongs to the forge router (relay pull request heads). The plan leaves the namespace out on both sides and the push names only the planned refs, so a flush neither updates, creates nor deletes a branch there (a primary branch of that name is not pushed either), and a relay head does not make a repository "out of sync" (which would otherwise re-push it on every flush). A copy-only branch under it is never pruned (see "Pruning") |
| Tag hint | `"sync_hint": {"url": "https://<bridge>/hooks/sync", "key_env": "<VAR>", "ca_file": "<optional CA bundle>"}`: after a push that succeeded, every tag it brought to GitHub (new, or at another object than before) is posted as `{"repository": "org/repo", "tag": "TAG"}` to the forge bridge, signed like Forgejo's deliveries (hex HMAC-SHA256 of the body in `X-Forgejo-Signature`, key from `key_env`; the signature reaches curl through its environment). The flush row lists `sync_hints` with each tag's HTTP status (202 = queued) or error; a failed hint never fails the push. Absent = no hint; held tags are not pushed and so not hinted |
| Creation | `create` makes one listed repository in its organisation under the same budgets: the per-organisation and overall daily caps, the overall `create_min_gap_secs` (default 300) between two creations, the pause, the kill switch and the ledger written before the POST. Visibility and description come from the caller (copied from the primary, never changed later); the repository is created with issues on, projects and wiki off (GitHub's wiki edit rights cannot be restricted through the API, so the description links to the Forgejo wiki). It refuses an existing repository instead of spending the creation. `flush --create` creates a listed destination that is missing (visibility and description from the configuration, never changed later) and fills it in the same run, under the same creation budgets; without the flag a missing destination is only reported |
| Quiet first push | a fresh destination receives every historical branch and tag, and those old commits still carry the old workflow files. `flush --create` therefore only creates the repository and switches repository Actions off, then proves the switch is off with a read; the FIRST PUSH follows on the next flush (the setting propagates asynchronously). After that push the gate waits 10 s (up to 30 s) before reading `actions/runs`, pauses the organisation if any run appeared, and only then switches Actions back on and proves they are on. The steady state stays enabled; the workflows in the code decide what runs. Only a test config sets `quiet_fill: false` |
| Authenticated reads | an executing flush reads the destination over HTTPS with the same credential as the writes, so a fill does not probe missing or existing destinations anonymously |
| Dispatch | starts one provider workflow (`workflow_dispatch`) on a `lane: "build"` repository only: the daily Actions-run budget, kill switch and paused organisation apply, the ledger entry is written before the first call, Actions are switched on once if they are off, and at most 10 `key=value` inputs are accepted (key `[A-Za-z0-9_-]+`, value at most 200 characters without control characters) |
| Delete | `delete-repo org/repo --allowlist FILE` deletes ONE old private repository. The allowlist (`{"repos": {"org/repo": {"head": "<40-hex>"}}}`, strict) names every deletable repository with the commit its default branch must still be at. Refused: an unlisted repository, a public one, a moved head, a kill switch, a paused organisation, and any deletion within `delete_min_gap_secs` (default 600, overall) of the previous one or beyond `deletes_per_day` (default 6). Both GitHub reads (private, head) run in the dry run too and need the credential; the ledger entry is written before the DELETE call. The dry run prints what would be deleted |
| Credential | read from the environment variable named by `--token-env` at the last moment and handed to git through `GIT_CONFIG_*` (an `http.extraheader`) or to curl through `--variable`/`--expand-header` for `create` and `dispatch`, never through arguments or files; `--origin`, `--api` exist for tests |

The configuration is JSON: `budgets` (optional), `repos` (`org/repo` to `{lane, source, lfs}`; a repository that is not listed is never pushed), `max_prune` (optional), `state_dir`, `paused_dir`,
`kill_switch`, `sync_hint` (optional). The pure decisions are `cfrg::gate`; `cfrg-cli/tests/it/gate_flush.rs` runs the executor against local bare repositories (including the empty LFS listing of a repository without LFS), `cfrg-cli/tests/it/gate_create.rs` covers the creation budget, gap and validation without network, and
`cfrg-cli/tests/it/gate_dispatch.rs` covers dispatch validation and refusals without network access; `cfrg-cli/tests/it/gate_delete.rs` and the unit tests in `cfrg-cli/src/delete.rs` cover the deletion refusals.
